# SilentGuard 可靠性升级

本次范围：完成已提出的八项优化；保留当前华为定位修复。开发分支为
`feature/huawei-location-reliability`，不直接提交或推送 main。

## 验收标准

1. **跨天补发**：待发送位置按实际投递批次绑定；邮件成功仅更新批次包含的事件。昨日积压不能因今日报告成功而消失。
2. **守护开关**：停止后拒绝新的自动短信/位置采集与投递；已排队自动任务暂停并保留，重新开启后恢复。明确手动 SOS/测试邮件的行为；已开始的 SMTP 发送不能撤回，界面说明。
3. **持久化发件箱**：Room 保存正文、收件人、事件关联、状态、尝试次数、错误及 Work ID。Worker 仅传任务 ID，支持自动重试、最终失败和手动重试；旧版 Worker 输入兼容过渡。SMTP 被接收不等于收件人已阅读；进程在 SMTP 成功后、写入状态前死亡时存在结果不确定边界，不能宣称严格 exactly-once。
4. **短信去重**：区分读取成功、重复和不可读；使用持久化唯一来源标识，重启和并发不会重复入库。读取收件箱与通知事件需匹配，不能把不相关的“最新短信”当成当前通知。
5. **配置**：显式加载状态，字段校验；定位间隔有正值和上限，邮件周期至少 15 分钟，端口为 1–65535；配置热更新；编辑设置不能覆盖守护状态。保存结果可见。
6. **后台与定位**：分阶段请求前台/后台权限，处理后台启动限制；维护实际心跳、持久化最近定位时间；重试按错误分类并限制退避上限。用户关闭定位或撤销权限时避免高频无效定位。不可承诺绕过 Android/OEM 后台限制。
7. **数据与隐私**：索引、分页、可配置保留期限、受保护的未发送事件；用户通过系统文件选择器导出数据并确认内容；排除敏感备份；移除内容日志；准确说明高德/SMTP 数据用途，在同意前不初始化地图 SDK。
8. **工程发布**：CI 执行单测和阻断错误级 Lint；Room schema 导出及真实迁移回归；Release 验证后再创建标签和发布，串行化版本分配。失败构建不能留下正式发布标签。

## 关键设计

- Room 升级采用非破坏性迁移，保留既有短信、轨迹与发送记录。
- 自动采集事件与待发送任务优先在同一事务创建；持续维护任务与事件关联。
- 位置批次限制数量和正文大小；待发送任务冻结内容及收件人，避免设置变更悄悄更换目的地。
- 任务执行前检查守护状态；并发 worker 通过数据库状态抢占任务。重试使用稳定任务标识和 Message-ID。
- 维护最近一次任务结果，尝试日志独立展示，避免旧失败永久计入当前故障。
- 数据导出包含敏感信息，采用用户主动触发的 Storage Access Framework，不请求广泛存储权限。
- 不引入自有服务端或不必要的第三方依赖。

## 验证矩阵

- 昨日积压 + 今日新位置、发送成功/失败/进程恢复、并发领取和重复调度。
- 停止守护时收到短信、任务排队时停止、重新开启恢复、手动 SOS。
- 重复通知、无 READ_SMS、重启后重复通知、快速连续不同短信。
- 无效配置、初次加载、保存期间切换守护、运行中修改间隔。
- 无权限、GPS/网络定位不可用、缓存过期、短暂失败与长期失败、服务恢复计时。
- v1/v2/v3 旧数据库迁移、外键/索引、分页顺序和保留清理保护。
- 数据导出完整性及转义、隐私同意和拒绝、备份排除。
- CI YAML 与发布逻辑静态验证，Debug/Release 构建、单测、Lint。
- 没有连接真机时，明确列出 OEM 权限/锁屏/开机恢复等尚未实测项目。
